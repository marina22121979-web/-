# Podcast Shorts Editing

Turn a conversation into independently useful clips. Each Short should give a viewer enough context, development and payoff to understand one idea without seeing the full episode. Build a varied portfolio when requested, with editable picture, audio and typography.

## Decisions that made the workflow work

1. Start with a specific reason to watch and an ending that completes the thought. Preserve the exchange that earns the conclusion. A standalone Short is a complete argument or story; an opening trailer can leave several questions unanswered.
2. Choose different angles across the set: a concrete story, operating lesson, technical explanation, disagreement, origin story or practical method. Several headlines on the same claim do not make a varied portfolio.
3. Let substance determine length within the user's constraints. The accepted set ran about 62–119 seconds; that is an example, not an algorithmic optimum. Preserve essential qualifications and whole words instead of padding or cutting to a magic duration.
4. Preserve accepted source grading and cleaned dialogue. A downstream recorder may already have applied a display look. Camera names and recording settings alone do not justify adding a log transform.
5. Keep faces and important gestures clear. The accepted architecture reserves large, separate picture and text areas, with speech-timed emphasis and occasional explanatory graphics. Use real font measurements and inspect native bounds.
6. Keep alternate cameras, captions, graphic layers and audio controls editable and easy for another editor to find. Use readable topic/phrase names and consistent speaker colors. Shared-mix speaking-turn tracks remain shared mixes; they are not isolated microphones.
7. Use one manifest for source spans, speaker turns, frame/sample clocks, words, graphic beats, output names and review metadata. Preserve raw ASR separately from corrected production words.
8. Check a representative motion proof and the difficult transitions before scaling the treatment. Once an accepted direction exists, continue the requested batch without adding approval gates.
9. Save and verify real outputs. A generated operation plan, successful tool response or existing MP4 alone does not establish delivery. Distinguish frame checks, audio measurements, sampled visual review and subjective listening.

## Native application access

Follow the available After Effects or Premiere connection skill and current tool schemas when using those applications. Inspect native state and IDs rather than replaying historical IDs. A documented batch is sequential, not transactional; inspect partial state before retrying a failed mutation.

Give one task ownership of each shared Adobe application and coordinate expensive jobs on the same machine. Prepare transcripts, manifests and documentation independently while another task owns the app. After a render timeout, the original script may still be running; wait for it to finish before dispatching even another status script. Do not use a script override to bypass that condition.

## Handoff

Match the handoff to the requested stage. For passage-selection or planning-only work, deliver the selects and plan, with missing media/timing evidence identified. For completed production, provide individual review MP4s, matching caption files, editable projects and a source/edit manifest. Use one per-short index to connect the playable review, editable project/composition, approved audio version, status and priority. Verify a representative manual revision using the [handoff checks](references/verification-delivery.md#verify-the-editor-can-continue). Recommend a few starting clips while retaining the full set. Keep earlier accepted trailers and episodes intact. State significant source or verification limitations without burying the review experience in implementation details.
